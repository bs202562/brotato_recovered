# Brotato 技能与数值设计学习指南

本手册研究的是你当前的 **Brotato_recovered 本地工程**。它包含恢复出的脚本、资源、中文翻译、本体及 DLC 目录，也可能包含测试或未启用内容。数值以本地配置和代码为依据，不套用网上其他版本的攻略。分析日期：2026-09-21。

阅读顺序建议：先看第 1～3 节建立体系，再看战斗与经济公式，最后选一个角色，交叉查阅角色、武器、套装和道具图鉴。文中的“设计解读”“学习推导”是基于实现的分析，不代表开发者公开意图。

## 1. 先理解：这个游戏的“技能”在哪里

这套系统以自动攻击和可组合被动为核心。“技能”不是一棵单独的技能树，而是分布在角色、武器、物品与事件处理器里。

| 层级 | 玩家获得什么 | 数值设计承担的任务 | 资源入口 |
| --- | --- | --- | --- |
| 角色规则 | 初始属性、属性收益倍率、限制、特殊成长条件 | 决定构筑方向及代价 | items/characters、dlcs 中的 character_data |
| 武器 | 攻击方式、伤害缩放、暴击、射程、特效 | 决定属性如何转化为战斗收益 | weapons、weapon_data、weapon_stats |
| 武器套装 | 按同类武器数量提供奖励 | 鼓励早期专精，制造混搭与集中持有的选择 | items/sets |
| 道具 | 常驻属性、触发效果、召唤、经济修正 | 形成协同、补短板或开启新循环 | items/all、effects/items |
| 升级奖励 | 单项或复合属性增量 | 提供商店以外的稳定成长通道 | items/upgrades |
| 波次与难度 | 敌人数量、成长、生成节奏和额外条件 | 检验构筑能否同时满足清场、生存、经济 | zones、items/difficulties |

**一次完整构筑的读法：角色改变收益 → 武器选择缩放属性 → 套装强化方向 → 道具加入触发链 → 经济购买更多成长 → 波次验证强度。**

源码入口：[角色结构](../../gdproj/items/characters/character_data.gd)、[武器结构](../../gdproj/items/global/weapon_data.gd)、[通用效果](../../gdproj/items/global/effect.gd)、[局内数据](../../gdproj/singletons/player_run_data.gd)。

## 2. 技能效果的八种基本类型

| 类型 | 典型形式 | 学习时应记录的参数 | 主要风险或限制 |
| --- | --- | --- | --- |
| 常驻加减 | 最大生命、护甲、攻击速度增减 | 数值、单位、是否受收益倍率影响 | 容易把百分比点与乘法倍率混淆 |
| 收益倍率 | 某属性的后续获得量提高／降低 | 作用属性列表、正负值、取整 | 不能当作当前面板直接乘倍 |
| 属性转换 | 每 X 点属性提供 Y 点另一属性 | 来源、目标、阈值、永久属性开关 | 循环依赖、临时属性重复计入 |
| 事件触发 | 命中、击杀、闪避、受伤、拾取、治疗后触发 | 事件、概率、次数、目标、内置冷却 | 高频事件可能造成爆炸式收益 |
| 状态条件 | 站定、移动、生命比例、燃烧中、无伤 | 条件、重置时机、持续时间 | 面板和实战覆盖率不同 |
| 时间／波次成长 | 每隔一段时间、每波结算、击杀累计 | 间隔、每次增长、是否跨波保留 | 早买与晚买的价值不同 |
| 独立输出实体 | 炮塔、地雷、宠物、额外投射物 | 实体基础伤害、缩放、冷却、继承规则 | 不能默认继承角色所有战斗属性 |
| 规则重写 | 武器槽、商品价格、禁用池、属性上限 | 替换还是相加、影响范围、例外 | 通常比同价格纯属性更能改变玩法 |

实现上，Effect 的存储模式有 SUM（相加）、KEY_VALUE（按键聚合）、REPLACE（替换）、APPEND_KEY（追加键）、APPEND_KEY_VALUE（追加键值）。同样是“获得一个效果”，其叠加规则可能完全不同。图鉴保留 storage_method；枚举顺序为 0、1、2、3、4。

复杂技能常用子效果拼装。设计一个类似系统时，可把每条技能写成：**触发条件 → 触发概率 → 目标 → 结算值 → 冷却／上限 → 重置时机**，再额外标记它读取基础属性、永久属性还是战斗临时属性。

源码：[Effect.apply](../../gdproj/items/global/effect.gd)、[属性收益修正](../../gdproj/effects/items/stat_gains_modification_effect.gd)、[属性转换](../../gdproj/effects/items/gain_stat_for_every_stat_effect.gd)、[子效果组合](../../gdproj/effects/items/effect_with_sub_effects.gd)。

## 3. 属性地图：每种数值解决什么问题

基础局内属性初始化为最大生命 10，其余这里列出的主要属性为 0；默认武器槽 6，闪避上限 60%，收获成长 5%。角色与其他规则会进一步修改它们。来源：[PlayerRunData.init_stats](../../gdproj/singletons/player_run_data.gd)。

| 属性 | 单位／结算角色 | 主要协同 | 学习重点 |
| --- | --- | --- | --- |
| 最大生命 | 可承受伤害的容量 | 护甲、恢复、以生命缩放的武器 | 容量与恢复速率是不同问题 |
| 生命再生 | 决定周期性回血间隔 | 护甲、长时间作战 | 不是每秒直接回复面板数值 |
| 生命窃取 | 命中后的概率回血 | 命中频率、多目标攻击 | 不是按伤害百分比吸血 |
| 百分比伤害 | 对对应输出通道增加伤害倍率 | 基础伤害、属性缩放 | 普通武器与结构物分开处理 |
| 近战伤害 | 由武器系数读取的平铺数值 | 高近战系数、频繁命中 | 不等于每把近战武器固定 +1 |
| 远程伤害 | 由武器系数读取的平铺数值 | 高频射击、多弹丸 | 低基础伤害武器通常更敏感 |
| 元素伤害 | 部分武器及燃烧的缩放来源 | 燃烧、特定武器 | 命中伤害与持续伤害要分算 |
| 攻击速度 | 缩短冷却并影响攻击动作 | 命中触发、窃取 | 动作时长和最短冷却限制收益 |
| 暴击率 | 与武器原生暴击率相加 | 高暴击倍率、暴击触发道具 | 不同武器的每点暴击价值不同 |
| 工程学 | 结构物或特定武器的缩放来源 | 炮塔、地雷、工程武器 | 结构物有独立攻速／伤害通道 |
| 范围／射程 | 远程全额增加，近战通常增加一半 | 覆盖率、走位安全 | 近战动作时长也与距离相关 |
| 护甲 | 非线性减伤系数 | 生命、所有恢复 | 减伤率递减不等于有效生命收益递减 |
| 闪避 | 可闪避伤害的概率规避 | 闪避触发、生存 | 默认 60% 上限；随机性不能保证免死 |
| 速度 | 移动能力修正 | 躲避、拾取、追击 | 会改变实际输出时间和材料回收率 |
| 幸运 | 影响品质抽样及部分掉落／触发 | 商店质量、幸运缩放道具 | 不是所有随机事件都统一乘幸运 |
| 收获 | 波后经济与经验来源 | 越早投资越多次结算 | 正收获会成长，无尽改为衰减 |

## 4. 伤害：平铺成长、倍率成长和取整

普通武器的核心计算顺序可整理为：

```text
缩放和 = Σ（属性值 × 该武器对应系数）
基础结算伤害 = int(max(1, 武器基础伤害 + 缩放和))
普通命中伤害 = max(1, round(基础结算伤害 × (1 + 百分比伤害/100 + 同通道额外加成)))
```

同通道额外加成包含相关套装加成、该武器属于爆炸输出时的爆炸伤害加成等。这里是常规路径；生命条件技能、特定武器行为、敌人承伤修正等仍可能继续改变结果。不能把所有写着“伤害 +X%”的来源都当作相互独立的乘区。

特别要注意：先做缩放加算，再转换为整数，之后做百分比放大。某次加点在整数阈值以下时，显示伤害可能暂时不变。

**实际配置算例：普通冲锋枪。** 基础伤害 3，远程伤害系数 0.5。远程伤害为 10、百分比伤害为 20% 时，先得到 3 + 10×0.5 = 8，再计算 round(8×1.2) = 10。这只是无其他修正的普通单弹伤害，不是整把武器每秒伤害。

来源：[冲锋枪 I 配置](../../gdproj/weapons/ranged/smg/1/smg_stats.tres)、[init_base_stats / apply_scaling_stats_to_damage](../../gdproj/singletons/weapon_service.gd)。

### 4.1 如何比较平铺属性与百分比伤害

学习推导：暂时忽略取整，如果当前结算基础是 B + kS，增加 ΔS 的相对收益约为 kΔS / (B+kS)。随着 S 增大，继续堆同一平铺属性的相对收益会下降。

例：冲锋枪未加远程伤害时，+2 远程伤害带来基础 3→4，约 +33.3%；已有 10 远程伤害时，同样 +2 使 8→9，约 +12.5%。因此不能把“远程伤害每点价值”当作固定价格。

### 4.2 暴击与理论输出

用于学习的常规期望近似：期望单次伤害 = 非暴击伤害 × [1 + p×(m−1)]，其中 p 是实际可用暴击概率，m 是暴击倍率。仅适用于普通的一次暴击判定，不包含特殊暴击规则、取整和事件触发收益。

理论输出还需乘以有效命中次数，并除以完整攻击周期。实际输出受命中率、敌人密度、散射、溢出伤害、目标切换和近战覆盖率影响。图鉴不提供一个容易误导的“万能 DPS 排名”。

## 5. 攻击速度：配置 cooldown 不是最终间隔

cooldown 的单位是 tick，代码约定每秒 60 tick。设攻速修正 a = 攻击速度 / 100，基础冷却 C：

```text
a ≥ 0：新冷却 = int(max(2, C / (1+a)))
a < 0：新冷却 = int(max(2, C × (1+abs(a))))
```

通用最短冷却为 2 tick，武器特殊冷却规则还能进一步干预。负攻速使用延长公式，所以 −100% 并不通过这条公式把攻击彻底关闭。

远程武器的基础显示间隔 = cooldown/60 + 2×recoil_duration。普通冲锋枪 C=4、recoil_duration=0.05，因此是约 0.1667 秒，而不是 4/60≈0.0667 秒。正攻速还会缩短 recoil_duration，不能只改变公式的一半。

近战基础显示间隔还包括突刺／挥击动作、返回与后坐时间。无加成时，可由代码写为：C/60 + [0.2 + (最大射程/70)×0.15]/2 + 0.2 + recoil_duration。实战动作还会根据目标距离更新；它是图鉴显示口径，不是所有场景的精确攻击周期。

带“每 X 次攻击额外冷却”的武器要单独算长周期平均输出。升级武器也可能改变特效、弹数与冷却，不能只看伤害列。

来源：[攻速与冷却](../../gdproj/singletons/weapon_service.gd)、[远程动作](../../gdproj/weapons/shooting_behaviors/ranged_shooting_data.gd)、[近战动作](../../gdproj/weapons/shooting_behaviors/melee_shooting_data.gd)、[武器基础参数](../../gdproj/weapons/weapon_stats/weapon_stats.gd)。

## 6. 防御：护甲、闪避、恢复是三个不同维度

### 6.1 护甲

正护甲 A 的承伤系数 = 15/(15+A)。负护甲的承伤系数 = 2−15/(15+abs(A))。玩家常规受伤路径应用护甲后 round，并至少承受 1 点伤害；不应用护甲的伤害不走这段减伤。

| 护甲 | 承伤系数 | 减伤率 | 忽略取整时，100 生命的有效生命 |
| --- | --- | --- | --- |
| 0 | 1.000 | 0% | 100 |
| 5 | 0.750 | 25% | 133.3 |
| 10 | 0.600 | 40% | 166.7 |
| 15 | 0.500 | 50% | 200 |
| 30 | 0.333 | 66.7% | 300 |
| −5 | 1.250 | −25% | 80 |

学习推导：正护甲有效生命约为 HP×(1+A/15)。减伤百分比看起来递减，但在固定生命下，每一点正护甲增加的有效生命近似相同。恢复也会因为护甲而变得更耐用。最低 1 点伤害、伤害取整和绕过护甲的伤害会破坏这个理想模型。

来源：[get_armor_coef](../../gdproj/singletons/run_data.gd)、[玩家 get_damage_value](../../gdproj/entities/units/player/player.gd)。

### 6.2 闪避

默认上限为 60%；实际读取 get_capped_stat，并且只在 dodgeable 为真时判定。学习推导：大量独立可闪避攻击下，平均有效生命可近似再除以 (1−闪避率)。例如 50% 闪避平均减半受伤次数，但它不能代替生命去抵挡一次致命命中。

### 6.3 生命再生

再生 R>0 时，基础回血间隔 = 5 / [1 + abs(R−1)/2.25] 秒，每次默认回复 1。R≤0 时常规再生被停止，代码中的 99 秒返回值不是负再生扣血机制。特殊道具可以改写每跳治疗。

| 再生属性 | 基础间隔 | 理想每秒回血 |
| --- | --- | --- |
| 1 | 5.000 秒 | 0.200 |
| 5 | 1.800 秒 | 0.556 |
| 10 | 1.000 秒 | 1.000 |
| 20 | 0.529 秒 | 1.889 |

来源：[再生公式](../../gdproj/singletons/run_data.gd)、[玩家再生处理](../../gdproj/entities/units/player/player.gd)。

### 6.4 生命窃取

命中时根据 weapon_stats.lifesteal 概率触发回血，通常回复 1，特殊效果能改变回复值。玩家 LifestealTimer 为 0.1 秒；冷却中不会重复兑现，所以基础模式下每秒至多约 10 次窃取回血，不能无限乘命中频率。

学习推导：在未碰到冷却、全部有效命中且持续缺血的理想条件下，回血速率约为“每秒命中数 × 窃取概率 × 每次回复量”。实战高频命中的冷却冲突会让结果低于这个简单期望。

来源：[窃取触发](../../gdproj/singletons/run_data.gd)、[on_lifesteal_effect](../../gdproj/entities/units/player/player.gd)、[0.1 秒计时器](../../gdproj/entities/units/player/player.tscn)。

## 7. 特殊输出：燃烧、结构物与事件链

### 7.1 燃烧不是每次命中无限叠层

BurningData 保存概率、基础伤害、duration、传播和缩放属性。duration 在每次燃烧结算时减 1，因此本工程中应理解成剩余结算次数，不能直接当秒数。单位基础燃烧计时器为 0.5 秒，也会受燃烧冷却修正影响。

已有燃烧时，代码对新旧 damage、duration、spread 等取最大值，而不是把每次命中伤害相加成新一层；不同来源和特殊条件仍由 apply_burning 路径处理。这使高频点火更多体现为覆盖和刷新，不能照搬直伤命中频率计算持续伤害。

来源：[BurningData](../../gdproj/effects/burning_data.gd)、[apply_burning / 燃烧结算](../../gdproj/entities/units/unit/unit.gd)、[燃烧计时器](../../gdproj/entities/units/unit/unit.tscn)。

### 7.2 工程结构物有自己的属性通道

init_base_stats 中，结构物／宠物不会直接使用普通角色攻速分支；结构物另有 structure_attack_speed、structure_percent_damage、structure_range 等属性。普通结构物的伤害百分比走结构物通道；宠物又有单独例外。工程学首先是一种缩放来源，具体读取多少仍看实体 stats.scaling_stats。

设计解读：独立通道能使工程构筑和手持武器构筑形成不同购买优先级，也能防止一条通用攻速属性同时无成本放大所有输出系统。读工程道具时，应同时展开其 stats 资源和特效脚本。

来源：[WeaponService](../../gdproj/singletons/weapon_service.gd)、[炮塔效果](../../gdproj/effects/items/turret_effect.gd)。

### 7.3 组合技能要分析“事件频率”

“命中时”效果与“击杀时”效果的表现不同：前者依赖命中数量，后者依赖敌人血量、清场速度和击杀归属。“闪避时”还会依赖受到攻击的次数，纯面板防御提高不一定线性增加触发数量。

学习时画出一条具体链：武器命中 → 概率窃取 → 治疗事件 → 治疗触发伤害。每条箭头都要检查概率、内置冷却和来源限制。工程中 main.gd 有治疗事件处理，玩家脚本有闪避与受伤事件处理，不能仅凭道具文案认为所有事件都互相触发。

## 8. 套装、合成与角色限制如何塑造流派

套装在持有同类武器至少 2 件时生效，取当前数量对应的一档 set_bonuses。**当前档位是总效果，不是把 2 件、3 件、4 件各档全部累加。** 超过配置档位数量时使用最后一档。来源：[局内套装更新](../../gdproj/singletons/run_data.gd)。

武器图鉴分别列出各品质的独立资源和 upgrades_into。研究升级收益时，比较基础伤害、缩放、完整间隔、暴击、弹数、穿透、弹跳和特效，而不是只比较武器颜色。

角色设计往往同时给“鼓励”和“阻力”。例如：

| 学习案例 | 当前配置中可直接确认的特征 | 设计解读 |
| --- | --- | --- |
| 全能型 well_rounded | +5 最大生命、+5% 速度、+8 收获 | 用生存、机动、经济三个小优势构造基准角色 |
| 斗士 brawler | 徒手武器 +50% 攻击速度；偏好近战伤害；禁用远程伤害道具组 | 用武器类别奖励与商品池限制一起强化定位 |
| 工程师 engineer | +10 工程学；工程学获得量 +25%；指定伤害属性获得量 −50%；带初始扳手规则 | 通过“未来属性收益”塑造长期选择，而非只给开局面板 |

以上是选择性拆解，完整正负效果见角色图鉴。角色 starting_weapons 是开局可选武器池，starting_weapon 类型效果才可能代表额外起始武器；不要把二者混成“角色开局持有全部武器”。

来源：[全能型](../../gdproj/items/characters/well_rounded/well_rounded_data.tres)、[斗士](../../gdproj/items/characters/brawler/brawler_data.tres)、[工程师](../../gdproj/items/characters/engineer/engineer_data.tres)。

## 9. 经济：强度不只来自伤害公式

### 9.1 收获的复利与回本时间

波后结算把收获与其他波后奖励合并；总额非负时获得材料并调用经验增加流程，总额为负时扣除材料。正收获结算后触发成长：增长量 = ceil(当前收获×成长率/100)，默认成长率 5%。无尽阶段（超过 nb_of_waves）改为每次减少 ceil(当前收获×20%)。

学习算例：若当前收获为 8，且没有其他修正，连续三次普通波结算的直接收获收入为 8、9、10，随后收获变为 11；这里向上取整使小数值也能每波增长至少 1。这个算例不含购买成本、其他波后奖励和经验倍率。

设计解读：同样 +8 收获，早期有更多复利与经验回报，临近结束则可能来不及回本。评价经济道具时应比较“还剩多少次可结算波次”，不是只比较当下材料数。

来源：[波后收入与收获成长](../../gdproj/main.gd)、[无尽衰减常量](../../gdproj/singletons/run_data.gd)。

### 9.2 商店价格

value 是基础价格，不是每波实际售价。默认单人、常规波数、没有折扣或通胀特殊修正时：

```text
售价 = int(max(1, 基础价格 + 波次 + 基础价格×波次×0.1))
```

例：基础价格 20，在价格函数传入波次 1、10、20 时分别为 23、50、80。完整函数还考虑武器专用价格、指定商品折扣、商品价格倍率、无尽系数。因而图鉴明确标注“基础价格”。

基础回收系数为 25%，再加 recycling_gains 修正并限制在 1%～100%，最后取整、至少 1，且不超过商店价值；基础价值为 1 的物品有单独分支。

来源：[get_value / get_recycling_value](../../gdproj/singletons/item_service.gd)。

### 9.3 刷新成本

```text
delta = int(max(1, 0.4×波次×sqrt(1+无尽系数)))
基础刷新费 = int(0.75×波次) + delta + delta×已刷新次数
实际刷新费 = ceil(基础刷新费 × max(0.1, 1+刷新价格修正/100))
```

在第 10 波、无额外修正时，刷新次数参数为 0、1、2，对应 11、15、19。递增费用为“继续追目标物品”设置机会成本。

### 9.4 商品池既随机，也受构筑引导

基础商店格数常量为 4，通常的武器抽样概率常量为 35%。当前波次不超过 2 时保障 2 把武器，不超过 5 时保障 1 把，锁定武器参与保障计数；武器槽规则、指定商品等还会影响最终结果。

代码还包含同武器、同套装、角色偏好标签的抽样机制，以及角色禁用物品／升级列表。这些概率不能直接相加理解成最终掉率，因为它们位于不同条件分支。

来源：[ItemService 常量、get_player_shop_items、_get_rand_item_for_wave](../../gdproj/singletons/item_service.gd)。

## 10. 品质、幸运与升级成长

品质抽样从高品质向低品质检查同一个随机数，因此下面列的是“命中该品质或更高档的阈值”，并非互斥概率。

| 品质 | MIN_WAVE 参数 | 每波阈值增长 | 阈值上限 |
| --- | --- | --- | --- |
| II | 0 | 0.06 | 0.60 |
| III | 2 | 0.02 | 0.25 |
| IV | 6 | 0.0023 | 0.08 |

波次基础阈值 = max(0, ((wave−1)−MIN_WAVE)×每波增长)。幸运 L≥0 时乘 (1+L/100)，负幸运时除以 (1+abs(L)/100)，最后与阈值上限取较小值。当前数据的这些高品质初始 BASE_CHANCE 都为 0。

第 10 波、0 幸运时，II、III、IV 阈值分别为 54%、14%、0.69%；根据从高到低的同随机数筛选，互斥概率为：IV 0.69%、III 13.31%、II 40%、I 46%。这是品质抽样层结果，资源池缺失、特殊规则等后续逻辑仍可能改变最终物品。

升级所需经验函数是 (3+level)²，实际传入“当前等级+1”，再乘 next_level_xp_needed 修正。也就是说，达到目标等级 2 的基础需求函数值为 25，达到 5 为 64，达到 10 为 169；这些是单次需求，不是累计经验。

升级奖励品质还有明确节点：等级 5 固定 II；10、15、20 固定 III；后续其他 5 的倍数走 IV 分支。具体属性奖励数值见升级图鉴，不把商店品质与升级品质完全等同。

来源：[get_tier_from_wave / get_upgrade_data](../../gdproj/singletons/item_service.gd)、[经验函数](../../gdproj/singletons/run_data.gd)。

## 11. 敌人与波次：玩家成长的另一半

基础敌人数据包含初始生命、每波生命增长、初始伤害、每波伤害增长、速度、击退抗性、价值和掉落概率等。基础曲线为：

```text
基础生命(w) = health + health_increase_each_wave×(w−1)
基础伤害(w) = damage + damage_increase_each_wave×(w−1)
```

最终数值继续乘以难度、玩家效果、多人、辅助设置、无尽及额外百分比修正。敌人基础数值图鉴因此列的是资源值，不是假设某难度下的最终战斗属性；它可能同时包含非敌人的通用 Stats 资源，按来源路径区分。

无尽系数的实现可以写为：n=max(0,w−20)，e = n(n+1)/200 × [2 + max(0,(w−35)×0.2)]。敌人生命的无尽因子约为 1+2.25e，伤害为 1+e；诅咒存在时又有放大。20 波以后不能继续只用线性每波成长外推。

波次资源控制 wave_duration、max_enemies、普通生成组与条件生成组。max_enemies 是上限字段，不能把它当成这波必定生成的总敌人数；总量还取决于组的生成间隔、数量和条件。波次图鉴保留生成组引用，便于继续追查。

设计解读：一波难度不仅是敌人血量，还包括生成密度、敌人行为、场地压力与持续时间。研究构筑时应分别检查清杂能力、精英／首领单体能力和生存恢复，不能用一个总 DPS 覆盖全部。

来源：[Stats](../../gdproj/entities/units/unit/stats.gd)、[EntityService](../../gdproj/singletons/entity_service.gd)、[无尽函数](../../gdproj/singletons/run_data.gd)、[波次结构](../../gdproj/zones/wave_data.gd)。

## 12. DLC 与恢复工程的阅读边界

工程中有 dlcs/dlc_1，包含诅咒等额外行为。图鉴按路径标记“DLC”或“本体目录”；这只是资源归属，不是已经验证的玩家可用列表。是否加载、解锁和加入池，需要再看单例场景、DLC 注册与存档状态。

诅咒相关脚本会影响物品强化和敌人尺度。例如 EntityService 在无尽修正中使用平均诅咒的平方根，生命通道除以 10，伤害通道除以 25。不要把这个规则误写为“每点诅咒固定增加相同比例敌人强度”。

图鉴的中文优先来自恢复出的 translations.csv。该 CSV 缺少的部分角色、武器、道具名称由本手册提供参考翻译，统一加上“〔参考译名〕”，不冒充游戏官方中文名；原始 ID 与来源仍保留。其他缺失的描述键保留原键。复杂脚本的运行时参数、局内累计值及自定义参数格式未被完整仿真，明确显示为“描述模板”，同时给出原始参数和行为脚本。**模板不是最终游戏面板。**

恢复工程可能经过本地修改，本手册未启动游戏进行战斗实测。已确认的是配置和代码逻辑；实战手感、实际可用内容、性能和最终平衡仍需运行验证。

## 13. 按设计问题学习，而不是背全表

推荐完成以下五个小练习，每次只改变一个条件，并用图鉴中的原始配置验算：

- **武器成长**：比较冲锋枪 I 与另一把远程武器，在远程伤害 0／10／20 时每次命中收益如何变化。把取整单独记录。
- **防御预算**：给定 50 最大生命、10 护甲，比较 +10 生命与 +5 护甲的理想有效生命收益，再讨论恢复和最低伤害的影响。
- **经济回本**：假设某经济升级花费 30，获得 +5 收获，分别在还剩 3 波和 10 波时算结算收益。区分基础收入与成长收入。
- **角色定位**：选工程师，把所有“有利规则、负面约束、偏好物品、不可取属性”写成四列，观察规则是否共同指向一种玩法。
- **组合技能**：选一件触发道具，写出事件链，估算每秒有效事件数，查清冷却与重置时机，再判断是否能与当前武器协同。

设计评估模板：

| 要回答的问题 | 应填写内容 |
| --- | --- |
| 玩家想解决什么 | 清杂／单体／容错／恢复／经济／机动 |
| 正向收益是什么 | 精确数值、单位、缩放和适用输出通道 |
| 代价是什么 | 价格、属性损失、武器槽、前置条件、操作风险 |
| 收益何时兑现 | 立即、战斗中、波后、多波复利 |
| 叠加怎样增长 | 相加、替换、独立触发、上限、冷却、取整阈值 |
| 哪些搭配会放大 | 高频命中、多目标、同类套装、属性转换 |
| 哪些条件使它失效 | 低敌人密度、首领阶段、满血、无目标、缺少剩余波数 |
