# Godot 3 战斗 3D 层

从原项目正常开局即可进入 3D 战斗，F8 临时切换 2D 对照。代码基于 Godot 3.6.3；不要用 Godot 4 打开并转换本工程。

`main.gd` 在原战斗初始化后延迟挂载 `battle_3d.gd`。原有移动、碰撞、武器、伤害、掉落、波次与商店仍由原系统处理。3D 层仅读取这些状态，以 Spatial、MeshInstance、Camera、灯光和骨骼动画呈现。不是把整张 2D 战斗贴在平面上。

## 坐标与输入

64 个战斗像素对应 1 个 X 轴世界单位；Z 轴额外除以相机俯角的正弦，以保持地面投影与原 Camera2D 一致。UI、伤害文字、鼠标瞄准仍用原来的坐标。自定义 Viewport 开启 `render_target_v_flip`，避免纹理叠到 UI 时上下颠倒。

## 资产接入

在 `models.json` 中注册：

```json
{
  "enemy": {
    "path": "res://combat3d/models/zombie_shopper_3000_walk.glb",
    "scale": 1.35,
    "offset_y": 0.0,
    "yaw": 0,
    "animation": "preset_biped_walk"
  }
}
```

优先匹配原场景完整 `res://...tscn` 路径，武器优先匹配 `weapon_id`；否则按 player/enemy/elite 等通用类别回退。导入后动画名称可能被 Godot 改写；找不到指定动作时选择第一条动画。当前主角播放待机，丧尸播放原地行走并按移动速度调节播放速度。模型朝向按 +Z 约定，主角的模型额外旋转 180 度朝向刷怪端。

推荐普通敌人 3,000 三角面、主角/精英 6,000 三角面、1K 贴图。Tripo 原始模型约 200 万面，务必先重拓扑再导出。动作必须勾选“导出骨骼”、具体动画以及“原地播放动画”。原始模型、生成词、积分记录见项目 `docs/combat3d-assets.json`。

缺失 GLB 时使用程序化 3D 造型；不会令战斗节点失去碰撞或伤害能力。目前有五套 Tripo 骨骼模型：保安、顾客丧尸、防暴队长、食堂厨师、生化清洁工。`survivor_wardrobe.gd` 为 64 个角色指定换色和骨骼配件；`models.json` 明确指定全部 82 个敌人身份（83 个原资源）的丧尸职能外观。这些仍包含共享基础体，并非 64 个独立幸存者或 82 个独立敌人精模。

`weapon_art.gd` 覆盖 78 个武器身份，`prop_art.gd` 制作炮塔、宠物、拾取物及弹体的立体造型。`art` 下的 312 张武器图标、64 张角色肖像、82 张敌人肖像来自实际 Godot 渲染；247 个道具图标通过原生 AtlasTexture 连接七张新图集。`scripts/connect-*-art.py` 与覆盖清单维护图标链接，`ui_gallery.tscn` 验证 651 个原数据资源都加载新图标并截图选择页面与商店。

导入 Tripo 骨骼时消除 Armature 的编辑器位置偏移；不可直接使用蒙皮 Mesh 的静态 AABB 推算脚底，否则会重复计算绑定空间偏移。配件通过 BoneAttachment 保持头部和躯干跟随动画。

## 生命周期与效果

通过场景树新增节点信号注册显示对象，使用弱引用跟踪逻辑节点。池内隐藏对象同步隐藏；退出树后释放显示对象。命中、暴击、防护、燃烧、治疗、升级和死亡事件创建立体发光碎片，短期效果节点上限为 160。弹体和爆炸读取碰撞形状控制体积；敌人攻击动画期间显示立体感叹号。

## 验证

项目 `scripts/test-combat3d.ps1` 执行第 1、12、20 波及第 1 波→结算→商店→第 2 波回归。`smoke_test.tscn` 使用原战斗场景、真实刷怪和武器；开启测试无敌并禁用常规保存。回归检查显示对象、骨骼动画、F8 切换、三个地面点的投影误差及波次结束。截图和日志写入项目 `docs`。

测试会运行项目现有的自动加载初始化；原恢复工程自身仍有未打包 mods、Attach 节点及退出时资源未释放的警告。无窗口 FPS 不代表手机或实际窗口的帧率，移动端性能仍需在目标设备测量。
